# Data folder

This is the only folder you need to touch to update the site. Drop your reanalyzed
files in here following the formats below, then run:

```bash
python3 scripts/build_db.py
```

from the repo root. That regenerates `site/data/ckr.sqlite` (and copies structures/
figures into `site/data/`), which is everything the static site reads at runtime.
Nothing else needs to change.

| column | meaning |
|---|---|
| `chemokine_id` | short unique key, e.g. `CXCL12` |

| `systematic_name` | e.g. "SDF-1" |
| `class` | CXC / CC / CX3C / XC |

### `pairs.csv` — one row per receptor–chemokine pair, structure optional
| column | meaning |
|---|---|
| `pair_id` | short unique key, e.g. `CXCR4_CXCL12` |
| `receptor_id` | must match a row in `receptors.csv` |
| `chemokine_id` | must match a row in `chemokines.csv` |
| `pair_type` | e.g. `validated`, `tested`, `predicted`, `known`, `novel` |
| `model_confidence` | numeric score from your modeling pipeline, if you have one |
| `structure_file` | filename of the PDB model in `data/structures/` — **leave all three structure columns blank** if you don't have a model for this pair yet (e.g. binding data only); the site just skips the structure viewer and contact diagram for it |
| `receptor_chain` | chain ID of the receptor in that PDB, e.g. `A` |
| `chemokine_chain` | chain ID of the chemokine in that PDB, e.g. `B` |
| `notes` | free text |

### `binding.csv` — one row per binding/pharmacology result (regenerated by `scripts/analyze_binding.py`, see below — don't hand-edit the numeric columns)
| column | meaning |
|---|---|
| `binding_id` | short unique key |
| `pair_id` | must match a row in `pairs.csv` |
| `assay_type` | e.g. "BRET saturation binding", "competition binding", "SPR" |
| `kd_nm` | Kd in nM, if applicable |
| `ic50_nm` | IC50 in nM, if applicable |
| `n_replicates` | |
| `analysis_method` | whatever software/pipeline produced the number, for provenance |
| `raw_data_file` | filename in `data/raw_binding/`, if you want the raw file linked |
| `legacy_figure` | filename in `data/legacy_figures/`, if there's an old static figure to keep around |
| `fit_bottom`, `fit_top` | three-parameter logistic fit params (baseline, Bmax; Hill slope is fixed at 1) — lets the site draw the actual fitted curve, not just scatter the raw points |
| `fit_r2` | fit quality |
| `notes` | free text |

Leave numeric fields blank rather than guessing — the site renders blanks as
"pending" instead of a number.

## Raw binding data → curves and Kd (`scripts/analyze_binding.py`)

Drop a CSV per receptor into `data/raw_binding/<RECEPTOR_ID>.csv` — first
column is ligand concentration in **M**, one further column per chemokine
with header `<CHEMOKINE_ID>-<tracer>` (e.g. `CXCL12-AZ568`) holding the BRET
ratio at that concentration. This is a direct/saturation binding assay (an
NLuc-tagged receptor titrated with an AZDye-labeled chemokine), not a
competition assay, so it produces a Kd, not an IC50.

Then run, from the repo root:

```bash
python3 scripts/analyze_binding.py
python3 scripts/build_db.py
```

The first command fits a three-parameter logistic curve per chemokine column
(GraphPad's "log(agonist) vs. response", Hill slope fixed at 1:
`Y = Bottom + (Top - Bottom) / (1 + 10^(LogEC50 - X))`, X = log10(concentration))
and **regenerates `data/binding.csv` from scratch** — don't hand-edit its
numeric columns, they'll be overwritten; `legacy_figure` is the one field it
carries over automatically. It also writes the raw (concentration, BRET)
points to `data/binding_curves/<pair_id>.csv` so the site can plot both the
real data and the fitted curve, on a log concentration axis. If a
chemokine's curve never rises meaningfully above baseline, it's reported as
no detectable binding (blank Kd) rather than fitting a number to noise —
see `MIN_DYNAMIC_RANGE` in the script if you want to tune that cutoff. If
the fitted EC50 falls outside the concentration range actually tested, the
notes say so — the number is still reported (it's the best estimate from
the curve's rising portion) but should be read as an extrapolation, not an
observed plateau.

A `pair_id` the script derives (`<RECEPTOR_ID>_<CHEMOKINE_ID>`) must exist in
`pairs.csv` — add a row for it (structure columns can stay blank) and a
matching row in `chemokines.csv` if it's a new chemokine, before running
`build_db.py`.

## Structure files

Put every PDB model referenced by `pairs.csv` in `data/structures/`. The build
script parses every residue of the receptor and chemokine chains straight out
of the PDB file (not just the ones that happen to contact each other) to
drive the circular contact diagram, so no separate residue list is needed.

## Contact overrides (optional)

By default the build script computes real inter-chain residue contacts directly
from each pair's PDB file (heavy-atom distance cutoff, see `scripts/build_db.py`),
so the chord/network plot on each pair's page reflects the actual structure —
not placeholder data. If you've already computed contacts yourself (e.g. a
different distance cutoff or a different contact-scoring method) and want to use
those instead, drop a CSV at `data/contacts/<pair_id>.csv` with columns
`receptor_resnum,receptor_resname,chemokine_resnum,chemokine_resname,distance_angstrom`
and the build script will use that file instead of recomputing.
